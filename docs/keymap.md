# Keymap

Complete hotkey inventory. Generated by diffing `keyconfigs.user` against a
`--factory-startup` run of the same Blender build (5.1.2), then split by **who
owns each change** — because most of the raw diff is not hand work.

| Owner | Items | Where it lives |
| --- | --- | --- |
| Me, by hand | **25** | [`extensions/ez_preset/profile.py`](../extensions/ez_preset/profile.py) |
| Easy Transform Axis Switch | 18 | The add-on re-applies these every load |
| Remember Last Used Axis | 19 | The add-on re-applies these every load |

The add-on-owned rows are listed at the bottom for completeness. They deliberately
**do not** appear in `profile.py`: those add-ons rewrite the same bindings on every
startup, so a second owner would mean a restore that fights whichever ran last.

## Keymap priority

This governs almost every decision below, so it goes first.

Blender resolves a keypress through the most specific keymap first:

```
modal  >  tool  >  mode (Mesh, Object Mode, Sculpt, Pose …)  >  space (3D View)  >  Window
```

A live binding in a higher-priority keymap **silently shadows** a lower one. There
is no warning and nothing in the UI hints at it. Three consequences that shaped
this setup:

- `Ctrl+1` → Local View lives in `3D View`. For it to fire in Object Mode, Object
  Mode's own `Ctrl+1` (subdivision level 1) had to be switched off.
- `Ctrl+2` → wireframe overlay lives in `Window`, the lowest priority of all. It
  never fired in Edit Mode, because `Mesh` bound `Ctrl+2` to select-mode expand.
  Moving expand to `Alt+2` fixed a bug I had not noticed I had.
- `F` → Frame Selected lives in `3D View`. `Mesh` bound `F` to Make Edge/Face, so
  `F` had to be switched off there.

## 1. Added from scratch

| Keymap | Key | Operator | Does |
| --- | --- | --- | --- |
| Window | `D` | `wm.context_toggle` | Toggle Affect Only Origins |
| Window | `Ctrl+2` | `wm.context_toggle` | Toggle wireframe overlay |
| Window | `4` | `wm.context_menu_enum` | Viewport colour-type menu |
| Object Mode | `Q` | `wm.tool_set_by_id` | X-Ray box select tool |
| Mesh | `Q` | `wm.tool_set_by_id` | X-Ray box select tool |

`D`, `Ctrl+2` and `4` sit in the **Window** keymap so they work in every editor,
at the cost of being the easiest bindings in the setup to shadow.

## 2. Moved off their default key

| Keymap | Now | Was | Operator |
| --- | --- | --- | --- |
| 3D View | `F` | `Numpad .` | `view3d.view_selected` |
| 3D View | `Ctrl+1` | `Numpad /` | `view3d.localview`, `frame_selected` off |
| Mesh | `Ctrl+E` | `E` | `view3d.edit_mesh_extrude_move_normal` |
| Mesh | `Shift+E` | `Ctrl+E` | `wm.call_menu` → edge menu |
| Object Mode | `1` | `Ctrl+0` | `object.subdivision_set` level 0 |
| Object Mode | `3` | `Ctrl+2` | `object.subdivision_set` level 2 |
| Object Mode | `X` | `X` | `object.delete`, `confirm` off |

`frame_selected` off is the interesting one: stock Local View reframes the view on
the isolated object, which loses your camera position. Off, it isolates in place.

Subdivision level 1 is not bound. Levels 0 and 2 on `1` and `3` is what the setup
actually has — worth deciding whether that is intentional or a leftover.

## 3. Switched off

| Keymap | Key | Was | Why |
| --- | --- | --- | --- |
| Mesh | `F` | `mesh.edge_face_add` | `F` is Frame Selected everywhere |
| Object Mode | `Ctrl+1` | subdivision level 1 | `Ctrl+1` is Isolate |
| Object Mode | `Ctrl+3/4/5` | subdivision levels 3–5 | Redundant after the move to `1`/`3` |
| Sculpt | `Ctrl+0…5` | subdivision levels 0–5 | Frees `Ctrl+1` and `Ctrl+2` in Sculpt |
| Sculpt | `Alt+1`, `Alt+2` | relative subdivision | Same |

**On losing `F` for Make Edge/Face.** This is the sharpest trade in the setup.
`F` is one of Blender's most-used modelling keys, and it is gone. It buys a single
consistent Frame Selected across all modes, which is the Maya reflex. Make
Edge/Face is still on the `Ctrl+V` vertex menu and the RMB context menu. If the
trade ever stops paying, this is the first row to revisit.

## 4. Added by this add-on

| Keymap | Key | Operator | Does |
| --- | --- | --- | --- |
| Mesh | `Ctrl+1` | `ez_isolate.toggle` | Isolate selection, unsync UVs |
| Mesh | `Alt+1` | `mesh.select_mode` | Expand to vertex |
| Mesh | `Alt+2` | `mesh.select_mode` | Expand to edge |
| Mesh | `Alt+3` | `mesh.select_mode` | Expand to face |

These four live in the **add-on keyconfig**, not the user keyconfig, so disabling
the add-on removes them cleanly and leaves nothing behind.

`Ctrl+Shift+1/2/3` (extend *and* expand) is untouched. It collides with nothing,
so there was no reason to move it — which does leave expand on `Alt` and
extend-and-expand on `Ctrl+Shift`. A deliberate asymmetry, not an oversight.

See [edit-mode-isolate.md](edit-mode-isolate.md) for how the toggle works.

## Owned by other add-ons

### Easy Transform Axis Switch — 18 items

Binds `W`/`E`/`R` to `etas.transform_tool` across ten mode keymaps, and switches
off whatever held a plain `W`, `E` or `R` press:

| Keymap | Disabled |
| --- | --- |
| Object Mode, Mesh | `W`/`E`/`R` → the old `wm.tool_set_by_id` bindings, and `R` → `transform.rotate` |
| Curve, Curves | `R` → `transform.rotate`, `E` → extrude |
| Armature | `R` → `transform.rotate`, `E` → `armature.extrude_move` |
| Grease Pencil Edit | `R` → `transform.rotate`, `E` → extrude |
| Lattice, Metaball, Point Cloud | `R` → `transform.rotate` |
| 3D View | `W` → `builtin.select_box` |

Its own `apply_keymaps()` documents an ordering constraint that also governs
`ez_preset`: Blender merges the add-on keyconfig into the active keymap **only for
keymaps the user keyconfig has not modified**. Deactivate a conflict first and the
keymap becomes user-modified, after which your own add-on bindings never fire. Add
the bindings, flush with `keyconfigs.update()`, *then* deactivate.

### Remember Last Used Axis — 19 items

With `enable_rmb_transform` on, it flips the right-mouse context menu from
**Press** to **Click** in 19 keymaps, freeing an RMB *drag* to transform along the
last used gizmo axis. Affected: Object Mode, Mesh, Curve, Curves, Armature,
Metaball, Lattice, Font, Particle, Pose, Sculpt, Vertex Paint, Weight Paint,
Image Paint, and the five Grease Pencil modes.

It keeps its own `keymap_backup` in its preferences so it can undo this, which is
exactly why `ez_preset` does not touch these rows.

### Node Wrangler — 87 items

All in the Node Editor keymap, all stock Node Wrangler defaults, none changed by
me. Listed in [`reference/keymap-diff.txt`](../reference/keymap-diff.txt) if you
need them.

## Unresolved

- **`2` in Object Mode.** Subdivision moved to `1` (level 0) and `3` (level 2).
  Level 1 has no binding. Either bind `2` → level 1, or accept the gap.
- **`Ctrl+1/2/3` in the UV Editor** still means select-mode expand, while the 3D
  viewport now uses `Alt+1/2/3`. Same operators, two different modifiers depending
  on which editor the cursor is over. Left alone because the request was scoped to
  the viewport, but it is inconsistent.
